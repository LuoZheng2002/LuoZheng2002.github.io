<article class="paper"><img class="paper-thumb" src="papers/treempo_image.png" alt="Thumbnail image for treempo"><div><h3 class="paper-title">TreeMPO: Fine-Grained Credit Assignment for LLM Training via Token-Level Trajectory Branching</h3><span class="paper-status">Manuscript</span><span class="paper-author-tag">First Author</span><p class="paper-meta"><a href="papers/treempo.pdf" download>Download paper</a></p><details><summary>Project description</summary><div class="paper-detail-content"><img class="detail-image" src="papers/treempo_image.png" alt="Detail image for treempo"><div class="paper-description"><section class="paper-abstract"><h4>Abstract</h4><p>We present TreeMPO, a reference-policy-free framework for fine-grained credit assignment in large language model training. The method targets mathematical reasoning while remaining compatible with tool-calling traces that interleave natural-language reasoning, fenced Python calls, tool responses, and final boxed answers. One of the identified biases is language bias, which indicates that the decision of LLM-as-a-judge can differ based on the language of the judged texts. In this paper, we study two types of language bias in pairwise LLM-as-a-judge: (1) performance disparity between languages when the judge is prompted to compare options from the same language, and (2) bias towards options written in major languages when the judge is prompted to compare options of two different languages. <article class="paper"><img class="paper-thumb" src="papers/sim_2_real_image.png" alt="Thumbnail image for sim 2 real"><div><h3 class="paper-title">When Simulation Lies: A Sim-to-Real Benchmark and Domain-Randomized RL Recipe for Tool-Use Agents</h3><span class="paper-status">Published - NeurIPS 2026 Evaluations and Datasets Track, poster</span><p class="paper-meta"><a href="papers/sim_2_real.pdf" download>Download paper</a> · <a href="https://arxiv.org/abs/2605.11928">arXiv page</a></p><details><summary>Project description</summary><div class="paper-detail-content"><img class="detail-image" src="papers/sim_2_real_image.png" alt="Detail image for sim 2 real"><div class="paper-description"><section class="paper-abstract"><h4>Abstract</h4><p>Tool-use language agents are evaluated on benchmarks that assume clean inputs, unambiguous tool registries, and reliable APIs. Real deployments violate all these assumptions: user typos propagate into hallucinated tool names, a misconfigured request timeout can stall an agent indefinitely, and duplicate tool names across servers can freeze an SDK. We study these failures as a sim-to-real gap in the tool-use partially observable Markov decision process (POMDP), where deployment noise enters through the observation, action space, reward-relevant metadata, or transition dynamics. We introduce RobustBench-TC, a benchmark with 22 perturbation types organized by these four POMDP components, each grounded in a verified GitHub issue or documented tool-calling failure. Across 21 models from 1.5B to 32B parameters (including the closed-source o4-mini), the robustness profile is sharply uneven: observation perturbations reduce accuracy by less than 5%, while reward-relevant and transition perturbations reduce accuracy by roughly 40% and 30%, respectively; scale alone does not close these gaps. We then propose ToolRL-DR, a domain-randomization reinforcement learning (RL) recipe that trains a tool-use agent on perturbation-augmented trajectories spanning the three statically encodable POMDP components. On a 3B backbone, ToolRL-DR-Full retains roughly three-quarters of clean accuracy and reaches an aggregate perturbed accuracy comparable to open-source 14B function-calling baselines while substantially narrowing the gap to o4-mini. <article class="paper"><img class="paper-thumb" src="papers/latent_skill_image.png" alt="Thumbnail image for latent skill"><div><h3 class="paper-title">SkiLT: What Agent Reinforcement Learning Actually Learns from a Latent Skill Library</h3><span class="paper-status">Submitted - AAAI 2027</span><p class="paper-meta"><a href="papers/latent_skill.pdf" download>Download paper</a></p><details><summary>Project description</summary><div class="paper-detail-content"><img class="detail-image" src="papers/latent_skill_image.png" alt="Detail image for latent skill"><div class="paper-description"><section class="paper-abstract"><h4>Abstract</h4><p>Retrieved skill libraries improve large language model agents, but rendering skills as text adds hundreds of prompt tokens at every decision step, and reinforcement learning pays that cost on every rollout. SkiLT asks whether the same conditioning survives full-actor, episode-reward RL in a compact latent form, and what such a library then contributes. A Composer initialized from the actor’s own base model compresses each of 44 SkillRL library entries into eight soft vectors, which are installed as retrievable vocabulary rows before the full actor is trained with GRPO. On the complete ALFWorld evaluation sets SkiLT reaches 90.0 valid-seen and 86.6 valid-unseen success against 87.9/79.9 for a released text-skill RL checkpoint under the same harness, with the skill section reduced from approximately 970 to approximately 140 tokens per step. That checkpoint was trained under a different recipe, so it anchors rather than controls the comparison, and a second SkiLT run reads 87.9/79.9, leaving the out-of-distribution margin unestablished. The mechanism study then revises the reading of this result. The installed rows were effectively frozen during the flagship run, with relative drift no greater than 2.4 times 10^-6: their activation-scale norms starved them under Adam and pushed nearly every update below the bfloat16 storage boundary. A 2x2 factorial isolates both failure modes, and a function-preserving repair restores row learning at RL scale. Yet substitutions drawn from the deployed bank or its empirical statistics, carrying no correct per-entry identity, are indistinguishable from it at the tests’ approximately plus-or-minus 7-point resolution, while removing the conditioning costs 21 points and retraining from an isotropic norm-matched bank does not recover. Compact latent conditioning therefore reaches text-skill RL performance under this harness, but we detect no contribution from code identity or per-entry distinctness, and the load-bearing property of the conditioning remains unidentified.</p></section><h4>Project description</h4><p><strong>SkiLT</strong> studies whether retrieved text-skill libraries for LLM agents can be compressed into <strong>compact latent skill tokens</strong> during reinforcement learning. It reduces the skill section from roughly <strong>970 tokens to 140 tokens per step</strong> while maintaining performance comparable to text-skill RL checkpoints on ALFWorld. The mechanism analysis further shows that the actor may adapt around nearly fixed skill rows, complicating the interpretation of what latent skill conditioning actually contributes.</p><p>I contributed to this <strong>AAAI 2027 submission</strong> as a co-author. My work included designing and implementing <strong>latent-form skill compression</strong>, integrating compact skill tokens into the GRPO workflow, evaluating against text-skill RL baselines, and helping analyze training dynamics to understand what agent RL actually learns from auxiliary skill memory.</p></div></div></details></div></article>
